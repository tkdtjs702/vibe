# 박스오피스 데이터 변경 검증

KOBIS 응답 파싱, 데이터베이스 저장, 캐시 매핑, 순위·매출·관객 지표 계산을 변경했을 때 결과의 정확성을 검증한다. 구현 자체를 대신하는 Skill이 아니며, 변경 범위에 맞는 최소한의 검증을 선택한다.

## ① 입력과 기준 찾기

- 변경된 코드와 관련 문서(`PRD.md`, `ARCHITECTURE.md`, `ERD.md`, `AGENTS.md`)에서 입력 필드, 기대 출력, 저장 모델, 예외 상태를 확인한다.
- KOBIS 원본 필드 `movieCd`, `movieNm`, `rank`, `openDt`, `salesAmt`, `audiCnt`, `salesAcc`, `audiAcc` 중 변경에 영향을 받는 필드를 식별한다.
- `rank`, `salesAmt`, `audiCnt`, `salesAcc`, `audiAcc`는 문자열로 수신될 수 있음을 전제로 한다. 숫자 변환 전후의 형식, 빈 문자열·비숫자 값·음수 등의 유효하지 않은 값 처리 기준을 확인한다.
- 데이터베이스를 변경했다면 `movies`, `query_periods`, `period_performances`의 PK·FK·유일 제약과 저장 단위를 확인한다. 특히 같은 `(period_id, movie_cd)`의 중복 저장 여부와 `period_type + target_date`의 중복 캐시 여부를 확인한다.
- 지표를 변경했다면 기준 기간, 단위(원·명), 반올림 방식, 집계 대상이 일간 데이터인지 확인한다. 일간·주간·주말 데이터를 서로 합산해 중복 집계하지 않는다.

## ② 변경에 맞춘 검사 선택

변경 내용에 해당하는 검사를 선택하고, 실행 가능한 프로젝트 명령어가 있으면 함께 실행한다. 명령어 또는 테스트 환경이 없으면 그 사실을 미실행으로 보고한다.

| 변경 종류 | 필수 확인 |
| --- | --- |
| API 응답 파싱 | 숫자 문자열이 숫자로 변환되어 정렬·계산되는지, `movieCd`가 문자열 식별자로 보존되는지, 잘못된 값이 조용히 0이나 `NaN`으로 처리되지 않는지 확인한다. |
| DB 저장·캐시 매핑 | 정상 응답이 영화·조회 기간·기간별 실적으로 올바르게 분리 저장되는지, PK/FK·유일 제약을 위반하지 않는지, 같은 캐시 키 저장이 idempotent한지 확인한다. |
| 순위·매출·관객 지표 | 알려진 입력 데이터로 순위, 총매출, 총관객수, 일평균, Top 5/10 결과를 손계산 또는 독립 쿼리 결과와 비교한다. |
| 기간·인사이트 집계 | 7·14·30일 경계가 정확한지, 일별 추이에 일간 데이터만 사용되는지, 날짜 순서와 누락 날짜 처리가 의도와 맞는지 확인한다. |
| 오류·빈 상태 처리 | 정상 빈 응답, 외부 API/내부 오류, 검색 결과 없음이 서로 다른 상태·문구·응답으로 처리되는지 확인한다. |

- 실제 KOBIS API를 호출하는 검증은 API 키를 출력·로그·커밋하지 않는 환경에서만 수행한다. 가능하면 고정된 테스트 fixture로 변환·저장·집계를 재현한다.
- 브라우저에서 KOBIS 키나 DB 비밀키가 노출되지 않는지 확인한다. `KOBIS_API_KEY`와 `SUPABASE_SECRET_KEY`는 이름만 참조하며 실제 값은 어떤 결과에도 포함하지 않는다.
- 단순 문구 수정, CSS·색상·간격·레이아웃 수정, 데이터 흐름과 무관한 문서 편집에는 이 Skill을 호출하지 않는다. 다만 그러한 변경이 오류 상태의 구분·표시 조건을 바꾸면 상태 처리 검사를 수행한다.

## ③ 결과와 중단 기준

검증 결과는 변경 범위별로 아래 세 상태 중 하나로 보고한다.

| 상태 | 보고 기준 | 보고 예시 |
| --- | --- | --- |
| 통과 | 선택한 검사가 실행됐고 기대값·제약·상태 처리가 모두 일치한다. | `통과 — salesAmt 문자열이 정수로 저장되고, 3일 총매출이 독립 계산값과 일치함.` |
| 실패 | 실제 결과가 기대값과 다르거나, 제약 위반·잘못된 집계·상태 혼동·민감 정보 노출이 확인됐다. | `실패 — 주말 데이터를 일간 추이에 포함해 총매출이 중복 집계됨.` |
| 미실행 | 필요한 명령어·테스트 fixture·권한·외부 의존성이 없어 검사를 실행할 수 없었다. | `미실행 — 테스트 스크립트가 아직 정의되지 않아 DB upsert 통합 테스트를 수행하지 못함.` |

- 실패가 확인되면 성공으로 해석할 수 있는 후속 결과만 나열하지 말고, 원인·영향 범위·재현 조건을 보고한 뒤 수정 또는 사용자 결정이 필요한 지점에서 중단한다.
- API 키, DB 비밀키, 프로덕션 데이터 변경, 외부 서비스 설정 변경이 필요한 검증은 해당 작업의 명시적 권한 없이는 수행하지 않는다.
- 통과만 보고하지 않는다. 실행한 검사, 실패한 검사, 미실행 검사와 그 이유를 함께 명시한다.
